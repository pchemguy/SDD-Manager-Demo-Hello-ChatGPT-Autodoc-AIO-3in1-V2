# T-007 — Electron host evidence

## Implementation and checks

Version advanced to 0.2.0. Selected exact development dependencies Electron 45.0.0 and @electron/packager 20.3.0; Node development minimum is 22.12.0 to match packager. Installation deliberately skipped the unrelated Linux Electron binary; the requested Windows runtime is produced by T-008. Browser dependencies/binaries remain pinned and reused in their dedicated environment.

The host loads the staged local browser renderer, retains its window until closed, removes the default application menu, disables renderer Node integration, enables context isolation/sandbox/web security, exposes no preload/IPC bridge, denies navigation/webviews/new windows and permission requests/checks, and quits after the window closes. Startup load errors exit explicitly. Initial staging contains only host, package metadata, project license and the existing built renderer.

RED: three behavioral checks failed for the entry seam: zero windows, missing navigation prevention and absent local renderer. GREEN: python tools/check.py electron reports 3 passed after staging and implementation. The real CJS host executes in a narrow modeled Electron API boundary; tests assert observable calls/policies, local asset existence and staged version. They are not source-text searches or native runtime execution.

Browser preservation: UI suite 2 passed in Chromium and 2 in Firefox at version 0.2.0. Source modules still share the same model/UI; no desktop color fork or persistence introduced. ASCII scripts and staged whitespace inspected. Upstream Electron 45 documentation supports Windows 10+; this is upstream support, not observed native compatibility.
